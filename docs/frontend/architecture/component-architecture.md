# Component Architecture

## 1. Composition model

The app uses a **page-centric** composition model:

- **Pages own everything.** Each page in `src/pages/` fetches its own data, keeps its own state, and renders its own header, sidebar, dialogs and footer. There is no shared layout component or `<Outlet/>`.
- **Sub-views are local components inside the page file.** `SuperAdminDashboard.tsx` declares `AdminSubjectView`, `SubjectQuestionPanel`, `MarksSchemaSection`, `SettingsSection`, `RoleManagementSection`, `YearCycleDropdowns` and others in the same file; `OCREvaluation.tsx` declares a local `StatusBadge` and many render helpers.
- **Pages embed pages.** A page component is reused as a child instead of a route:

```text
SubjectDashboard ──(selected subject)──▶ OCREvaluation ──(popup)──▶ StandaloneOCREvaluation
                                                                      ├─ ScriptExtractorPanel
                                                                      │    ├─ ExtractionControls
                                                                      │    └─ ExtractionOutputTabs
                                                                      └─ ImageInspectorModal
SuperAdminDashboard ─ activeSection 'dashboard' (no menu item) ─▶ SubjectDashboard | AdminSubjectView ─▶ OCREvaluation
SuperAdminDashboard ─ imports SandboxDashboard but never renders it
```

- **Shared building blocks** are thin: shadcn/ui primitives, one shared header control (`HeaderAccountControls`), the `components/ocr` set, and one icon.

Styling: Tailwind utility classes inline (`className`), design tokens as CSS variables in `src/index.css`, theme extension in `tailwind.config.ts`, and `cn()` from `src/lib/utils.ts` to merge classes.

### Project-specific customisations

| File | Change vs. stock shadcn |
|---|---|
| `ui/loader.tsx` | Not a shadcn component. `PageLoader` renders a full-screen white overlay at `z-[70]` with the fixed text "Please wait…" — used as the single blocking loader across pages. |
| `ui/dialog.tsx` | Imports `Tooltip*` parts (adds a tooltip to the dialog chrome). Requires the app-level `TooltipProvider`. |
| `ui/sonner.tsx` | `position="bottom-right"`, `expand`. Reads `useTheme()` from `next-themes` without a provider (resolves to `"system"`). |
| `hooks/use-toast.ts` | `TOAST_LIMIT = 1`, `TOAST_REMOVE_DELAY = 2000`. |

Native HTML elements are also used where a primitive exists — e.g. `Register.tsx` uses plain `<select>` for Customer/Organization, and many pages use raw `<button>`.

## 4. Guidelines for new components

1. Put reusable UI in `src/components/` (or `src/components/<feature>/`), not inside page files. The giant page files are the main maintenance cost of this codebase.
2. Use the existing primitives from `@/components/ui/*` and `cn()`; add new shadcn primitives with the shadcn CLI so they follow `components.json`.
3. Use `toast` from `sonner` for notifications (the live pattern); the shadcn `useToast` path is effectively unused.
4. Use `PageLoader` for blocking operations to keep the loading experience identical.
5. Do not read `sessionStorage` directly inside new presentational components; accept values as props (as `HeaderAccountControls` mostly does), and use `getSessionCodes()` from `src/lib/session.ts` in containers.

1. System Overview

The Knowledge Base System is an advanced document management and retrieval platform that leverages artificial intelligence to provide accurate, contextual answers from your document repositories. This system combines state-of-the-art natural language processing techniques with vector embeddings to create an intelligent question-answering solution.

Key Features

  • Intelligent Document Processing: Automatically processes and indexes documents from multiple formats
  • Vector Embeddings: Converts text into high-dimensional vectors for semantic search
  • Advanced Retrieval: Uses similarity search and MMR algorithms for optimal information retrieval
  • Query Enhancement: Automatically rewrites queries for improved search coverage
  • Multi-Model Support: Compatible with various large language models for answer generation
  • Customizable Settings: Fine-tune system parameters to match your specific requirements

System Architecture

The system operates through a multi-stage pipeline designed to maximize accuracy and relevance:

  1. Document Ingestion: Upload and validate documents in supported formats
  2. Preprocessing: Clean and structure document content
  3. Chunking: Split documents into optimally-sized segments
  4. Embedding Generation: Convert text chunks into vector representations
  5. Vector Storage: Store embeddings in high-performance databases
  6. Query Processing: Enhance and execute user queries
  7. Response Generation: Generate accurate answers using retrieved context

5. Processing Settings

5.1 Retrieval Strategy

The retrieval strategy determines how the system identifies and selects relevant document chunks when processing user queries. Choosing the appropriate strategy significantly impacts answer quality and relevance.

Similarity Search

Overview

Similarity search employs vector distance calculations to identify documents most semantically similar to the input query. This method calculates cosine similarity between the query embedding and all document embeddings in the vector store.

How It Works

  1. Query is converted to a vector embedding
  2. Cosine similarity is calculated against all document vectors
  3. Documents are ranked by similarity score
  4. Top-k most similar chunks are retrieved

When to Use

  • Straightforward factual queries
  • Questions with clear, specific intent
  • General question-answering scenarios
  • When precision is more important than diversity
Example: Similarity Search

Query: "What is our refund policy?"

Process: The system retrieves the 5 most similar chunks that directly discuss refund policies, procedures, and related terms.

Result: Highly relevant chunks specifically about refunds, all from similar sections of policy documents.

MMR (Maximal Marginal Relevance)

Overview

MMR balances relevance and diversity to provide comprehensive yet non-redundant information. This algorithm iteratively selects documents that are both relevant to the query and dissimilar to already selected documents.

How It Works

  1. Calculate relevance scores for all documents
  2. Select the most relevant document first
  3. For subsequent selections, balance relevance against diversity
  4. Penalize documents too similar to already selected ones
  5. Continue until k documents are selected

When to Use

  • Complex queries requiring multiple perspectives
  • Exploratory information gathering
  • Broad topic coverage needed
  • Avoiding redundant or repetitive information
Example: MMR Search

Query: "Tell me about our company benefits"

Process: The system retrieves diverse chunks covering different benefit categories - health insurance, retirement plans, paid time off, etc.

Result: Comprehensive coverage of multiple benefit types rather than multiple similar chunks about one benefit.

5.2 Number of Reranking Candidates (k)

Overview

The k parameter controls the initial retrieval breadth before the reranking stage. This setting directly impacts the comprehensiveness of information considered when generating answers.

Processing Pipeline

Understanding how k affects the retrieval pipeline:

  1. Initial Retrieval: For each rewritten query, retrieve k candidate chunks
  2. Query Multiplication: The system generates 3 query variations
  3. Total Candidates: k chunks × 3 queries = 3k total candidates
  4. Reranking: All 3k chunks are scored for relevance
  5. Final Selection: Top 3 chunks from each query (9 total) are sent to LLM
Example: k=5 Pipeline

Original Query: "When did Tarun graduate?"

Rewritten Queries:

  1. "Tarun graduation date"
  2. "When did Tarun graduate"
  3. "when did the tarun graduatred"

Process:

  • Query 1: Retrieves 5 chunks → Reranked → Top 3 selected
  • Query 2: Retrieves 5 chunks → Reranked → Top 3 selected
  • Query 3: Retrieves 5 chunks → Reranked → Top 3 selected

Result: 9 highly relevant chunks sent to LLM

Recommended Values

k Value Total Candidates Final Chunks Use Case
3 9 9 Fast processing, simple queries
5 15 9 Balanced performance and coverage
10 30 9 Comprehensive search, complex queries

5.4 Overlap Percentage

Overview

Overlap creates redundancy between adjacent chunks to preserve contextual continuity across chunk boundaries. This prevents information loss when concepts span multiple chunks.

Available Options

  • 10%
  • 15%
  • 20%
  • 25%
  • 50%

How Overlap Works

Example: Chunk Size = 100 tokens, Overlap = 20%

Original Text:

"Machine learning is a subset of artificial intelligence. It enables computers to learn from data. Deep learning is a subset of machine learning. It uses neural networks with multiple layers."

Without Overlap (0%):

  • Chunk 1: "Machine learning is a subset of artificial intelligence. It enables computers to learn from data."
  • Chunk 2: "Deep learning is a subset of machine learning. It uses neural networks with multiple layers."
  • Issue: Context break between chunks

With 20% Overlap:

  • Chunk 1: "Machine learning is a subset of artificial intelligence. It enables computers to learn from data."
  • Chunk 2: "to learn from data. Deep learning is a subset of machine learning. It uses neural networks with multiple layers."
  • Benefit: Maintains context continuity

Selection Guidelines

Overlap % Use Case Characteristics
10% Distinct topics Minimal overlap, faster processing, independent sections
15-20% Standard use Balanced context preservation, general documentation
25% Related concepts Important context preservation, interconnected topics
50% Technical documentation Maximum context, critical continuity requirements

5.8 Process Documents

Processing Workflow

After configuring all settings, initiate document processing by following these steps:

  1. Review all uploaded documents and configurations
  2. Click the "Process Documents" button
  3. Monitor the processing progress indicator
  4. Wait for completion confirmation

Processing Operations

During processing, the system performs the following operations:

  1. Document Parsing: Extract text from uploaded files
  2. Text Cleaning: Remove formatting artifacts and normalize text
  3. Chunking: Split documents according to configured chunk size and overlap
  4. Embedding Generation: Create vector embeddings for each chunk
  5. Vector Storage: Store embeddings in the selected database
  6. Metadata Indexing: Save chunk metadata and relationships
  7. Configuration Storage: Persist processing settings for future queries

Processing Time Factors

Processing duration depends on several factors:

  • Number of Documents: More documents require proportionally more time
  • Document Size: Larger files take longer to process
  • Chunk Size: Smaller chunks create more embeddings, increasing processing time
  • Overlap Percentage: Higher overlap generates more chunks
  • Embedding Model: API-based models may have rate limits
  • Database Type: Write performance varies by database

Processing Status: The system provides real-time progress updates during processing. Once complete, the knowledge base is immediately ready for querying.

6. Query Processing Pipeline

Overview

The query processing pipeline employs a multi-stage approach to maximize retrieval accuracy and answer quality. This sophisticated pipeline combines query enhancement, retrieval, reranking, and response generation.

Model Selection for Answer Generation

The system supports multiple language models for generating responses. Each model offers different capabilities and performance characteristics:

Model Description Best For
GEMMA Efficient open-source model Cost-effective deployments, general queries
GPT_OSS Open-source GPT alternative Privacy-focused applications, local deployment
MISTRAL High-performance open model Complex reasoning, detailed explanations
GPT-4o OpenAI's most capable model Maximum accuracy, complex queries, critical applications

Query Enhancement Pipeline

Step 1: Query Rewriting

The system automatically generates multiple variations of the original query to improve retrieval coverage and handle potential ambiguities.

Query Rewriting Example

Original Query: "when did the tarun graduatred"

Rewritten Queries:

  1. "Tarun graduation date"
  2. "When did Tarun graduate"
  3. "when did the tarun graduatred"

Purpose: Creates multiple variations to capture different phrasings and improve retrieval success rate

Rewriting Strategies

  • Spelling Correction: Fixes typos and misspellings
  • Rephrasing: Generates alternative phrasings
  • Keyword Extraction: Creates keyword-focused queries
  • Original Preservation: Retains original query for comparison

Step 2: Document Retrieval

For each rewritten query, the system retrieves k candidate chunks from the vector database using the configured retrieval strategy.

Retrieval Formula: Total Retrieved Chunks = Number of Rewritten Queries × k

Example: 3 queries × 5 candidates = 15 total chunks retrieved

Step 3: Reranking

The reranking stage applies a specialized model to score all retrieved chunks based on their relevance to each specific query. This process ensures that only the most pertinent information is passed to the language model.

Reranking Process

  1. All retrieved chunks are evaluated against each query
  2. A relevance score is computed for each chunk-query pair
  3. Chunks are ranked by score for each query
  4. Top 3 chunks from each query are selected
  5. Final set of 9 chunks is prepared for response generation
Reranking Example

Input: 15 candidate chunks (5 per query)

Process:

  • Query 1: 5 chunks scored and ranked → Top 3 selected
  • Query 2: 5 chunks scored and ranked → Top 3 selected
  • Query 3: 5 chunks scored and ranked → Top 3 selected

Output: 9 highly relevant chunks sent to LLM

7. Response Generation

Tree of Thought Approach

The system employs a Tree of Thought reasoning methodology to generate accurate and well-reasoned responses. This approach involves generating multiple reasoning paths and selecting the most confident answer.

Response Structure

Each response includes the following components:

  • Answer: The final, concise answer to the query
  • Rewritten Queries: All query variations used in retrieval
  • Thoughts: Multiple reasoning paths considered
  • Best Thought: The selected reasoning path with highest confidence

Example Response

{ "answer": "Tarun graduated in May 2024.", "rewritten_queries": [ "Tarun graduation year", "When did Tarun graduate", "when did the tarun graduatred" ], "thoughts": [ "Thought 1: Tarun's education section in his resume states that he pursued a Bachelor of Engineering in Artificial Intelligence and Machine Learning at Alvas Institute of Engineering and Technology from October 2020 to May 2024. Since this timeline aligns with typical graduation dates for undergraduate programs, it is reasonable to infer that Tarun graduated in May 2024.", "Thought 2: Tarun's work experience includes internships starting in March 2024 and October 2024. These internships suggest that he was actively working in his field during and shortly after completing his undergraduate studies. Based on this, his graduation likely occurred around May 2024, as indicated in his education timeline.", "Thought 3: Tarun's educational timeline indicates he completed his SSLC (high school equivalent) in April 2018, intermediate (pre-university) in April 2020, and then pursued his bachelor's degree from October 2020 to May 2024. Following this sequential progression, his graduation year for his bachelor's degree is most likely May 2024." ], "best_thought": "Thought 1: Tarun's education section in his resume states that he pursued a Bachelor of Engineering in Artificial Intelligence and Machine Learning at Alvas Institute of Engineering and Technology from October 2020 to May 2024. Since this timeline aligns with typical graduation dates for undergraduate programs, it is reasonable to infer that Tarun graduated in May 2024." }

Thought Process Breakdown

Thought 1: Primary Evidence Analysis

  • Reviews main source of information
  • Identifies direct evidence
  • Makes primary inference
  • Assesses confidence level

Thought 2: Cross-Reference Validation

  • Checks supporting information from other sections
  • Validates consistency across sources
  • Identifies corroborating evidence
  • Flags any contradictions

Thought 3: Contextual Analysis

  • Examines broader context
  • Considers temporal relationships
  • Evaluates logical progression
  • Confirms timeline consistency

Best Thought Selection

The system evaluates each thought path based on:

  • Evidence Strength: Quality and directness of supporting information
  • Logical Coherence: Internal consistency of reasoning
  • Confidence Score: Statistical certainty of the conclusion
  • Source Reliability: Trustworthiness of referenced documents

Benefits of Tree of Thought Approach

Query Enhancement

  • Multiple query variations capture different phrasings and perspectives
  • Improves recall of relevant information
  • Handles typos and ambiguities effectively
  • Increases robustness of retrieval

Reranking Advantages

  • Ensures only the most relevant chunks reach the LLM
  • Reduces noise and irrelevant information
  • Improves answer quality and accuracy
  • Optimizes token usage in LLM context

Transparent Reasoning

  • Multiple perspectives are explicitly considered
  • Reasoning process is visible and auditable
  • Best answer is selected based on evidence strength
  • Facilitates debugging and system improvement

Structured Responses

  • Status indicators for error handling
  • Clear answer presentation
  • Reasoning transparency for verification
  • Traceable decision-making process

9. Troubleshooting

Poor Answer Quality

Symptoms

  • Irrelevant or inaccurate responses
  • Missing critical information
  • Contradictory answers
  • Overly generic responses

Solutions

Issue Solution Setting to Adjust
Not enough context Increase candidates retrieved Increase k value (5 → 10)
Context breaks Improve chunk continuity Increase overlap (15% → 25%)
Too granular Larger context windows Increase chunk size (250 → 500)
Redundant information Improve diversity Switch to MMR retrieval

Slow Processing

Symptoms

  • Long document processing times
  • Slow query responses
  • System timeouts
  • High resource utilization

Solutions

Cause Solution
Too many small chunks Increase chunk size to reduce total chunk count
High overlap Reduce overlap percentage (25% → 15%)
Database performance Switch to FAISS for better performance
Large retrieval sets Reduce k value if appropriate
API rate limits Implement request throttling or use local models

Missing Information

Symptoms

  • System cannot find relevant information
  • Answers indicate information is not available
  • Incomplete responses

Diagnostic Steps

  1. Verify Document Upload: Confirm all relevant documents are uploaded and processed
  2. Check Document Content: Ensure the information actually exists in source documents
  3. Review Query Phrasing: Try alternative phrasings and terminology
  4. Increase Retrieval Breadth: Increase k value for broader search
  5. Check Chunk Boundaries: Information might be split across chunks
  6. Verify Embedding Quality: Consider upgrading embedding model

Solutions

  • Add missing documents to knowledge base
  • Reprocess with different chunk settings
  • Use higher-quality embedding models
  • Increase overlap to preserve context
  • Switch retrieval strategy (Similarity → MMR)
